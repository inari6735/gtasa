This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Development Commands

### Environment Setup
```bash
# Start development environment with database and mail services
docker compose up -d

# Install PHP dependencies
composer install

# Run database migrations
php bin/console doctrine:migrations:migrate

# Build and watch Tailwind CSS
php bin/console tailwind:build --watch
```

### Testing
```bash
# Run all tests
./vendor/bin/phpunit

# Run tests with coverage
./vendor/bin/phpunit --coverage-html var/coverage

# Run specific test
./vendor/bin/phpunit tests/SomeTest.php
```

### Development Tools
```bash
# Clear cache
php bin/console cache:clear

# Debug routes
php bin/console debug:router

# Debug services
php bin/console debug:container

# Create new entity
php bin/console make:entity

# Create new migration
php bin/console make:migration

# Start development server
symfony serve -d
# or
php -S localhost:8000 -t public/
```

### Database Operations
```bash
# Create database
php bin/console doctrine:database:create

# Drop database
php bin/console doctrine:database:drop --force

# Show migration status
php bin/console doctrine:migrations:status

# Execute specific migration
php bin/console doctrine:migrations:execute --up VERSION
```

## Architecture Overview

This is a **Symfony 7.3 web application** focused on **media upload and management** with user authentication. The application uses modern Symfony patterns with:

### Domain-Driven Structure
- **Shared layer**: Contains cross-cutting entities (`User`, `Media`, `UploadSession`) and repositories
- **Media domain**: Handles file upload logic with support for both direct uploads and chunked uploads
- **Security domain**: Manages user registration and authentication with email verification

### Key Architectural Patterns
- **Command/Handler pattern**: Used in `MediaUploadHandler` for processing form submissions
- **Service layer**: Business logic separated from controllers (e.g., `Uploader`, `MediaCreator`)
- **Repository pattern**: Data access abstraction for entities
- **DTO pattern**: Input validation through `MediaInput` DTOs
- **Value Objects/Enums**: Type safety with `MediaVisibility` enum

### Storage Architecture
The application uses **Flysystem** with multiple storage adapters:
- **Public storage**: For publicly accessible media files
- **Private storage**: For private user media
- **Temporary storage**: For chunked upload processing

### Technology Stack
- **Backend**: PHP 8.4+, Symfony 7.3
- **Database**: MySQL 8.0 with Doctrine ORM
- **Frontend**: Stimulus + Turbo (Hotwired), Tailwind CSS v4.1.11
- **File handling**: League Flysystem for storage abstraction
- **Email**: Symfony Mailer with Mailpit for development
- **Testing**: PHPUnit 12.3

### Key Features
- **User registration/authentication** with email verification
- **File uploads** with support for both direct and chunked uploads
- **Media visibility controls** (public/private)
- **UUID-based entities** for security
- **Responsive UI** with Tailwind CSS

## Development Notes

### Entity Management
- All entities use UUID primary keys generated by Doctrine
- Automatic timestamp management with `@PrePersist` and `@PreUpdate` callbacks
- Entities follow strict typing with `declare(strict_types=1)`

### Media Upload Flow
1. **Direct uploads**: Single file through `MediaUploadHandler`
2. **Chunked uploads**: Multi-part upload via `UploadSession` for large files
3. **Storage routing**: Based on `MediaVisibility` enum (public/private)

### Form Handling
- Uses Symfony Forms with custom form types (`MediaType`, `RegistrationFormType`)
- DTOs for input validation and data transfer
- CSRF protection enabled

### Security
- Email-based authentication with verification required
- Password hashing with Symfony's security component
- Session security with CRC32C password hashing in serialization
